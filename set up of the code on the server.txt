 backend-deployment:
  app  bget.db  docker-compose.yml  requirements.txt

   requirements.txt   - required libraries for the code.
   docker-compose.yml - single-service stack for a FastAPI backend.
   bget.db    	     - is a SQLite database that sets up 3 tables: users, feedback, toolkit_config.

   app:
    crud  database.py  __init__.py  main.py  models  __pycache__  router  services  utils
     main.py     - entry point of the Play-O-Meter backend API
     database.py - sets up the database connection for the entire backend. It's the bridge between FastAPI and the bget.db file.
    
     crud:
      feedback.py  __init__.py  __pycache__  toolkit.py  users.py
       feedback.py - This file handles all database operations for the feedback table
       toolkit.py  - This file handles all database operations for the toolkit_config table
       users.py    - This file handles all database operations for the users table
        
     models:
      database_models.py  feedback.py  __init__.py  __pycache__  toolkit.py  users.py
       database_models.py - This file defines the actual database tables using SQLAlchemy, these models define what gets stored in bget.db.
       feedback.py	  - This file defines the data shapes for feedback, it controls what data looks like going in and out of the API, separate from the database model.
       toolkit.py         - This file defines the data shapes for toolkit, it controls what data looks like going in and out of the API, separate from the database model.
       users.py           - This file defines the data shapes for users, it controls what data looks like going in and out of the API, separate from the database model.
       
     router:
      auth.py  biometric.py  feedback.py  __init__.py  match_data.py  __pycache__  riot.py  toolkit.py  videos.py
       auth.py	      - This file handles user authentication, signup and login, via two POST endpoints
       biometric.py   - This file handles biometric data retrieval via two GET endpoints.
       feedback.py    - This file exposes the feedback API endpoints — it's the HTTP layer that connects incoming requests to the crud/feedback.py functions you saw earlier.
       match_data.py  - This file handles match data browsing — finding, listing, and reading match files from the data directory. It has 4 endpoints:
       riot.py        - This file acts as a proxy between the Play-O-Meter backend and the Riot Games API. Instead of the frontend calling Riot directly (which would expose the API key), all Riot requests go through this backend router.
       toolkit.py     - File dialog endpoints (/select-file, /select-obs, /select-tobii) — open native Windows file picker dialogs using tkinter so the user can browse for the main.bat, OBS, and Tobii executables. This only works because the backend runs locally on the player's machine, not on a remote server.
       videos.py      - This file serves video files to the frontend — one single endpoint that streams .mp4 match recordings.
     
     services:
      biometric_processor.py  __pycache__
       biometric_processor.py - This is the core analytics engine of the Play-O-Meter — it takes a merged CSV file and produces a complete biometric analysis of a player's match performance.

     utils:
      auth.py  __pycache__
       This is the authentication utility — it handles password hashing and JWT token logic used across the rest of the backend.
